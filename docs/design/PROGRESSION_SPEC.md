# Progression specification

## Cadence definitions

- Purchase frequency: any spend; not inherently meaningful.
- Visible reward: rate/progress/node/summary change.
- Meaningful decision: at least two viable options with different future consequences.
- System reveal: a new concept or control with immediate context.
- Automation: a repeated execution becomes a policy decision.
- Transformation: chapter state changes representation/function.

## Natural Numbers target bands (`PROVISIONAL`)

| Event | Target |
|---|---:|
| First interaction | 5–15 seconds |
| Passive production | 15–30 seconds |
| First meaningful choice | 1–3 minutes |
| Intuition appears | 1–3 minutes |
| First project | 5–10 minutes |
| First upgrade | 8–15 minutes |
| First milestone | 5–10 minutes |
| Queue-one automation | 15–30 minutes |
| First Insight | 15–30 minutes |
| First approach choice | 30–45 minutes |
| Fourth Attention | 35–60 minutes |
| Capstone | 60–100 minutes |
| Publication | 60–120 minutes |

First offline return is tested after any absence ≥60 seconds; the summary appears only when something changed or a decision blocked.

## Dead-interval gates

While open: visible progress at least every 30 seconds, a useful optimization/decision within 12 minutes after onboarding, and a system reveal within 25 minutes until the capstone. Early 30-minute sessions target no >3-minute interval without an actionable or clearly forecast event. Offline waits may be longer because a plan and ETA precede them.

## Campaign envelope

First Publication spans 1–3 sessions. Later chapters grow from hours to days, with the finite initial campaign targeting 4–8 weeks. Each Publication compresses solved work so UI/state complexity does not grow monotonically.
